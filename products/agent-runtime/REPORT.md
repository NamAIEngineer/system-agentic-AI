# Agent runtime report

## Outcome

Implemented a local-first persistent task queue. New tasks use a local Qwen3-8B MLX model with a bounded plan/tool/verification loop, workspace-contained file tools, network-denied command execution, and persistent conversation state. A Codex backend remains available only through explicit `--backend codex`; existing database rows retain their Codex backend during schema migration.

## Files and architecture

- `agentic_runtime.py`: Python standard library CLI, SQLite migration/state machine, worker lock, local/Codex dispatch, resume handling, and LaunchAgent management.
- `local_agent.py`: local model conversation loop, bounded tools, workspace containment, command sandbox, and saved-session recovery.
- `../../scripts/local-agent-model-service.py`: loopback-only MLX model LaunchAgent manager with offline loading.
- `../../scripts/agentic-runtime`: stable workspace CLI entrypoint.
- Runtime DB and logs: `~/Library/Application Support/SystemAgenticAI/runtime/`; never stored in versioned product files.
- Queue has no network listener. SQLite uses WAL/FULL sync; runtime directory, DB, logs, lock, and plist use owner-only permissions.

## How to run

See `README.md`. Core commands are `service install`, `submit --workspace ...`, `list`, `status ID`, `logs ID`, and `resume ID`. Cloud execution requires `submit --backend codex`.

## Limits

- LaunchAgents run after interactive login, not before login/FileVault unlock. `caffeinate -is` prevents idle sleep while the model server runs; it cannot keep a closed MacBook lid awake.
- Work is sequential. Interrupted local tasks resume the persisted conversation; tasks with no saved conversation and interrupted Codex tasks without a captured session require explicit `--new-session`.
- The 8B quantized model is materially less capable than hosted frontier models; the 16 GB M1 constrains context and generation speed.
- Local tools intentionally cannot publish, deploy, message, purchase, or access the internet. Such actions need a separately authorized integration.
- The smoke proves local inference, tool calls, file read/write, and command verification; it is not a broad quality benchmark or proof that every coding task will succeed.
- macOS sleep/power loss and external service actions cannot be guaranteed by the queue itself.
- Exact-session resume after a forcibly interrupted active Codex turn was not exercised end-to-end; behavior is implemented using `codex exec resume` and requires its stored session.
- PDF/OCR/audio/video tools remain separate capabilities and are not prerequisites for the core queue. Read-only public browser research is integrated as described below.

## TypeSafe hybrid browser route (2026-10-14)
